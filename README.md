AutoLedger — файловый движок хранения данных для автосалона

Собственная минималистичная СУБД на чистом Python: без внешней базы данных, без SQL — хранение, индексация и выборка данных реализованы вручную поверх обычных файлов.

Идея

Вместо того чтобы полагаться на готовую БД, каждая "таблица" (модели, автомобили, продажи) хранится в отдельном текстовом файле с записями фиксированной длины. Рядом — отдельный индекс-файл ключ → номер строки, который позволяет находить нужную запись за одно обращение (seek()), не читая файл целиком — тот же принцип, на котором строится индексация в промышленных СУБД.

Продажи организованы как неизменяемый журнал (append-only лог): запись о продаже никогда не удаляется и не перезаписывается. "Отмена продажи" — это не физическое стирание истории, а снятие ключа из индекса активных продаж, сама запись остаётся в логе. Это тот же подход, на котором строятся системы вроде event sourcing.

Возможности (CarService)
add_model / add_car — регистрация новых моделей и автомобилей
sell_car / revert_sale — продажа и отмена продажи с сохранением истории
update_vin — обновление ключа с синхронизацией индекса
get_car_info — сборка полной информации об автомобиле join'ом трёх файлов (авто → модель → продажа) вручную, без SQL
top_models_by_sales — агрегация: топ-3 модели по количеству продаж
Технологии

Python, Pydantic (валидация и (де)сериализация моделей в JSON), pytest (тесты), файловый ввод-вывод низкого уровня (seek, фиксированная адресация записей).

Как запустить
bash
pip install -r requirements.txt
export PYTHONPATH=$PYTHONPATH:$(pwd)/src
pytest tests

Также есть Docker-окружение (docker-compose up -d --build) для запуска без локальной настройки Python.
